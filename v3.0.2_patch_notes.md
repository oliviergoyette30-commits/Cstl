# v3.0.2 Patch Notes — 2026-04-19

## Summary

CSTL v3.0.2 resolves six latent ambiguities identified during an internal
audit of v3.0.1. The fixes fall into two categories: two glyph separations
(eliminating cases where a single symbol carried two distinct meanings)
and four new grammar rules (giving operational criteria where an encoder
could previously oscillate between valid options).

The audit methodology followed the same empirical pattern that produced
v3.0.1: stress the spec along four angles (usage ambiguities, semantic
overlaps, uncovered zones, internal contradictions), then validate
candidate fixes against a targeted benchmark.

## The six fixes

### Fix #1 — `⟳` / `⟲` separation

**Before**: `⟳` appeared in both Part 2.2 (Relations, "irreversible
transformation") and Part 2.4 (Dynamics, "transformation in progress").
Encoders could not distinguish ongoing process from completed outcome.

**After**: `⟳` denotes transformation achieved (∙ → ◉). `⟲` denotes
transformation in progress (Dynamics family).

### Fix #2 — `«` / `⇐` separation

**Before**: `«` appeared in both Part 2.5 (Time, "past") and Part 2.8
(Transmission Modes, "archeological"). These are fundamentally
different concepts (temporal property of a relation vs. transmission
strategy of an agent).

**After**: `«` remains the temporal-past operator. `⇐` is the new
glyph for the archeological transmission mode.

### Fix #3 — Rule 8: `(!)` vs `[MUST]`

**Before**: Part 2.9 defined both symbols but the spec did not specify
when to use one, the other, or both. Empirically, encoders applied
both in a fixed template regardless of sentence content.

**After**: Rule 8 (Part 5) establishes surface-marker-based
disambiguation with a 3-step decision procedure, stating that the two
glyphs are mutually exclusive by default. Targeted re-test: 5/5.

### Fix #4 — Rule 9: `↔` vs `ℝ`

**Before**: Part 2.7 defined `ℝ` via a Dice similarity threshold
(> 0.85), which is not computable by an LLM encoder at inference time.
The result was de-facto overlap with `↔`.

**After**: Rule 9 (Part 5) preserves the formal threshold for strict
parsers and adds a linguistic-marker criterion for LLM encoders.
Similarity markers (`same`, `identical`, `in unison`, `echo`) trigger
`ℝ`; structural co-regulation markers trigger `↔`.

### Fix #5 — Rule 10: `⊃` vs `⊃[]`

**Before**: The pair was intentional (the notation `⊃[]` visually
contains `⊃`), but the spec did not document how an encoder should
discriminate between direct constraint on actions and meta-constraint
on relations.

**After**: Rule 10 (Part 5) formalizes the object-vs-meta distinction
with concrete examples.

### Fix #6 — Rule 11: `≡` / `≠` / `∿`

**Before**: Three transmission modes with gradient semantics but no
operational criterion for where to draw the boundaries.

**After**: Rule 11 (Part 5) gives observation-based criteria: `≡` if
words preserved; `≠` if words differ but meaning preserved; `∿` if
new information added.

## Empirical validation

Full methodology and raw data in `experiments/20260419/e3_v302_benchmark.csv`.

### Phase 1 — regression test (20 sentences)

The 20-sentence E3 benchmark was re-run with the v3.0.2 prompt. Zero
sentences fell from "preserved" to "lost". Two sentences moved from
"preserved" to "partial" (T02 future-uncertainty, F03 catalysis),
both on nuances outside the zones fixed by v3.0.2. These are
attributed to LLM stochastic variance and not to the v3.0.2 changes.

| Metric | Value |
|--------|-------|
| CSTL v3.0.2 | 0.950 |
| JSON baseline | 0.650 |
| CSTL — JSON | +0.300 |

### Phase 2 — targeted fixes (10 new sentences)

Ten new sentences constructed specifically to stress the zones fixed
by Rules 8–11. Nine preserved, one lost. The lost case (NEW10) is a
test-design artifact: transmission modes (`≡`/`≠`/`∿`) are
relational properties between a source and a reformulation, not
properties of an isolated sentence.

| Metric | Value |
|--------|-------|
| CSTL v3.0.2 | 0.900 |
| JSON baseline | 0.450 |
| CSTL — JSON | +0.450 |

### Rule 8 re-test (5 sentences)

After strengthening Rule 8 to state mutual exclusivity by default:

| Sentence | Expected | Obtained | Result |
|----------|----------|----------|--------|
| "You must sign this document by Friday." | `[MUST]` only | `[MUST]` only | ✓ |
| "Sign it!" | `(!)` only | `(!)` only | ✓ |
| "You must sign this immediately!" | `(!)` + `[MUST]` | `(!)` + `[MUST]` | ✓ |
| "Please review this when you can." | neither | neither (`[MAY]`) | ✓ |
| "Employees are required to report incidents." | `[MUST]` only | `[MUST]` only | ✓ |

## What does NOT change

- Theorem 1 (k=9 uniqueness). Impact: none.
- 65-symbol semantic alphabet size. Impact: none (two glyph substitutions,
  net count unchanged).
- 121-token syntactic grammar. Impact: none.
- E1 compression results. Impact: none (structural changes do not affect
  compression benchmarks).
- E4 collision-free theorem results. Impact: none.

## What DOES change

- Grammar rule count: 7 → 11.
- `CSTL_v3_Spec.docx`: updated to v3.0.2 with glyph substitutions in
  tables 2.4 and 2.8, four new rules inserted before Part 6, and a
  new changelog entry. Backward-compatible with v3.0.1 in the sense
  that a v3.0.1 payload remains a valid v3.0.2 payload, but a
  v3.0.2 encoder will output cleaner disambiguations.
